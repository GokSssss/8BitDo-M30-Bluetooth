M30 Companion 1.33 — статус крестовины на рисунке и отдельные окна

ПРОЙДЕНО
- assembleDebug, lintDebug, assembleDebugAndroidTest: BUILD SUCCESSFUL. Lint без Error/Fatal. Инструментальные проверки скомпилированы, но не запускались на устройстве/эмуляторе.
- Все 17 core-наборов пройдены. Новый DpadDetectorTest: до ввода unknown, KEYCODE_DPAD/HAT, XY, центрированные Z/RZ и RX/RY, отсечение BRAKE/GAS/курков/шума, зеркальные key+axis и mixed, удержание SELECT с направлением, нейтраль/фокус, повторное наблюдение после смены, раздельные контроллеры, сброс/отключение.
- Обозначение под крестовиной основного PadView теперь меняется: НЕ ОПРЕДЕЛЕНО / D-PAD / ЛЕВЫЙ СТИК / ПРАВЫЙ СТИК / НЕОДНОЗНАЧНО. Нажатие на крестовину или её подпись открывает окно сочетаний SELECT + ↑/←/→, удержание 5 секунд. Окно объясняет повторную проверку после отпускания, обновляет статус/исходные сигналы при живых нажатиях.
- Данные — предположение по сигналам Android, не чтение настройки прошивки. До нового ввода нет автоматического выбора по нажатию экранного пункта. Часть Android-драйверов преобразует оси. Настоящий аналоговый геймпад не позволяет доказать физическое происхождение оси; функция предназначена для M30.
- События нескольких семейств за один кадр/короткий интервал дают неоднозначность. RX/RY предпочтительнее Z/RZ при их наличии, чтобы не читать покоящиеся оси курков за правый стик. Отпускания и нейтраль не заменяют последнее наблюдение; новая пара/сброс очищает его. SELECT с направлением сбрасывает старое наблюдение и не выдаётся за успешное переключение.
- Статус и свидетельства раздельны в ControllerSession двух слотов, присутствуют в справке, диагностике и JSON-отчёте (dpad_observation, dpad_observation_evidence, dpad_is_firmware_readout=false).
- Диагностика из «Дополнительно» открывается Dialog поверх текущего экрана с затемнением, собственной прокруткой, прежними переключателями/устройствами/логом/отправкой отчёта и фиксированной кнопкой «Закрыть». Блок не вставляется в основной ScrollView.
- Диалог сочетаний и диагностика маршрутизируют реальные KeyEvent/MotionEvent в общий обработчик Activity; у окна своя диспетчеризация, поэтому фоновой Activity недостаточно. Закрытие/потеря фокуса отпускают удержанные кнопки, выключение диагностики очищает сторонний монитор. Перерисовка основной страницы при смене источника не теряет ссылки на живую диагностику.
- SmokeInstrumentation дополнена проверками отдельных окон, сохранения прокрутки основной страницы, касания подписи, отмены свайпа и живого нажатия/отпускания виртуального M30 в диагностическом окне. Эти сценарии только скомпилированы.
- Прошивочный механизм, проверка DAT, телеметрия/оценка режима 1.32, справочная круговая геометрия и ButtonGuideView побайтно сохранены. Статичная миниатюра сохраняет D-PAD и прежний размер подписи; динамическая подпись и действие применяются только к основной интерактивной схеме. Другие кнопки не заменены.
