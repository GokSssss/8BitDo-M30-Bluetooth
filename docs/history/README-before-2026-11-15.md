# M30 Companion1.59

Package app.m30.companion/code60. Update over1.58 without uninstalling; same stable signature. Native minSdk26/targetSdk35.

Rename is system-first: public setAlias on API31+ after exact-MAC companion association/permission. If unavailable/denied/cancelled, offer an unchecked local-label choice; only explicit confirmation saves the preference and opens title/number. Existing labels remain editable; errors never save labels or change preferences automatically.
Connection is native-first: new createBond on supported old Android; saved devices use public BluetoothDevice.connect on API37+ after companion association/permission. Earlier Android gets an explicit external-settings choice. Successful request initiation is not connected HID/InputDevice proof. Owner-slot intent survives OS round trips; cancellation releases it.
The compact Compatibility disclosure stores both user choices for the host. Both default false. Connection close is a centred vector icon in a square48dp target with accessibility caption.

## Changes in 1.59

Single-pane portrait aligns both help buttons with Keys and places version/firmware above them. Short phone landscape bounds the diagram by viewport height, preserving its aspect ratio and normal control/text sizes. Explicitly opening Bluetooth scrolls to its heading after layout; closing restores the previous scroll position. In short landscape the Bluetooth panel fills the viewport. Saved open state remains visible and keeps its owning slot after recreation. Wide tablet/TV paired layout is unchanged.
Regression tests first reproduced 1.58 failures, then passed on short 640x320 and 780x360 phone windows, including large text, both owners, return positions and recreation. PNGs are actual Android Views rendered headlessly, not hardware evidence.

## Changes in 1.58

Explicit native button metrics fit Russian connection captions at larger font sizes. Two remote-focusable help actions sit below the controller; narrow views show icons and keep accessibility descriptions. Transparent focus outlines follow button/tab contours. Dialogs have explicit opaque surfaces, including create().show(); fallback checkboxes move focus to Continue, with no preference committed until confirmation.
Old Android with Location off offers explicit system Bluetooth search. Saved pairs remain readable without Location. The choice persists for subsequent searches; no private API or promise of bypassing firmware restrictions. Known TV system inputs (including virtual-search) cannot occupy gamepad slots; the all-input test still sees their events.

## Установка и подключение

1. Скачайте `M30-Companion-1.37.apk` на телефон и откройте файл. Android может попросить разрешить установку из выбранного файлового приложения. Это тестовая сборка, подписанная отладочным ключом, не публикация в Google Play.
2. Откройте M30 Companion и нажмите строку Bluetooth / Connect в шапке: в поле под джойстиком раскроется компактная Bluetooth-панель.
3. Выключите M30: START 3 секунды; если завис — 8 секунд.
4. На выключенном M30 удерживайте **B + START**, затем отпустите. Отдельно удерживайте **PAIR 2 секунды**.
5. Нажмите «Искать геймпады», предоставьте запрошенный доступ, выберите **8BitDo M30 gamepad** и подтвердите сопряжение. Затем нажмите «Проверить кнопки». Если пара сохранена, но ввода нет — откройте системные настройки Bluetooth/аксессуаров TV.
6. Откройте «Кнопки». Здесь общий тест клавиатуры, пульта и геймпадов: название источника, коды, нажатие/отпускание и оси. Для выбранного источника M30 показана панель 16 кнопок без рисунка джойстика. Касания не имитируют нажатия.
7. Если подсветка не совпадает, откройте страницу нужного джойстика → «Дополнительно» → «Исправить подсветку кнопок», выберите подпись и нажмите реальную кнопку. Назначения сохраняются отдельно для устройства и выбранного профиля.

## Что изменилось в 1.37

- Bluetooth в шапке раскрывает панель в поле с кодом нажатия на главном экране: слева «Найти устройство» (сохранённые пары), «Системные настройки», «Выполнить поиск»/«Остановить поиск»; справа прокручиваемый список геймпадов. Пары загружаются без радио при уже предоставленном CONNECT, новый поиск запускается явно. Back или повторный Bluetooth закрывает панель. Полный прежний экран остаётся в «Дополнительно → Поиск геймпадов Bluetooth».

## STAR и HOME

В 1.0 STAR не имела начального назначения, а HOME предполагалась как BUTTON_MODE (110). Поэтому пришедшее нестандартное событие могло не подсвечивать физическую кнопку. Теперь любое доставленное выбранному источнику событие видно независимо от назначения.

Кроме этого, STAR управляет Turbo внутри контроллера в режимах Android/Windows/macOS, а в Switch служит Screenshot. HOME может перехватываться Android до Activity. То, что событие существует на уровне системы, не гарантирует его доставку приложению. Новый монитор помогает отличить неизвестное назначение от другого логического источника; он не обходит системный перехват и не запрашивает Accessibility или root.

## Возможности и ограничения

- Состояние активного устройства ввода Android, выбор среди нескольких геймпадов, список сохранённых Bluetooth-пар (по отдельному разрешению «Устройства поблизости» на Android 12+).
- Подсветка кнопок и диагоналей, поддержка D-pad как клавиш, HAT, левого и правого стика, сырые коды и значения осей, журнал последних 40 переходов.
- Счётчик проверенных кнопок, переназначение, очистка теста, текстовый JSON-отчёт через системное меню «Поделиться».
- Профиль режима выбирается **вручную**. Оценка совместимости по имени/VID/PID — лишь предположение. Приложение не переключает прошивку или режим M30.
- Первичные назначения взяты из Android-схемы официальной инструкции. При другой прошивке или режиме используйте настройку кнопок.
- Заряд показывается только при наличии BatteryState от Android 12+. Отсутствие процента не означает разряженную батарею. На старых Android — «нет данных».
- Сопряжение и переподключение Bluetooth HID выполняются системными настройками Android. Приложение не использует скрытые API, не сканирует окружение и не требует геолокацию.
- STAR/Turbo и HOME могут перехватываться прошивкой или Android. Достигать 16/16 необязательно; PAIR вообще не является игровой кнопкой.
- Потеря фокуса, отключение и смена устройства сбрасывают удерживаемые кнопки. История сессии хранится в памяти; назначения и выбранный профиль — на устройстве.
- USB OTG тоже поддерживается, если Android видит устройство как геймпад.
- Приложение не измеряет задержку Bluetooth. Счётчик отражает переходы сырых входных сигналов, включая оси.

Памятка содержит подключение Android TV и рекомендации по шестикнопочному управлению Sega. Основная поставка ориентирована на телефон/планшет; совместимость интерфейса с конкретным Android TV требует отдельной проверки.

## Сборка

Требуется JDK 17+, Android SDK 35. Gradle Wrapper 8.11.1 и Android Gradle Plugin 8.9.2 включены/зафиксированы. Укажите `sdk.dir` в своём `local.properties` или задайте `ANDROID_HOME`.

```sh
./gradlew assembleDebug lintDebug
./test-core.sh
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. В Windows используйте `gradlew.bat`. Не добавляйте в репозиторий `local.properties`, сборочные каталоги и личные ключи подписи.

Отладочный ключ создаётся Android SDK локально. При пересборке с другим ключом для установки потребуется удалить предыдущую тестовую сборку; это удалит сохранённые назначения.

## Автоматические проверки

`test-core.sh` дополнительно проверяет неизвестные/неоднозначные идентификаторы, изоляцию источников, сохранение последнего кода после UP, границу истории, очистку монитора и неизвестные scanCode. Также проверяет повторы, одновременные нажатия, отпускание, потерю фокуса, конфликты назначений, диагонали, объединение источников D-pad, смену левого/правого стика, отсечение шумов и сброс.

В `app/src/androidTest` есть самостоятельный `SmokeInstrumentation` без тестовых библиотек. Он проверяет запуск, вкладки, выбор режима и отбрасывание ввода от другого устройства. При виртуальном геймпаде дополнительно проверяет крупный код, неназначенную кнопку, сохранение кода после UP и отдельный монитор других источников. Если в Android есть устройство с именем `M30 Virtual Test`, дополнительно проверяет обработку кнопок и HAT в Activity.

```sh
./gradlew assembleDebug assembleDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w app.m30.companion.test/app.m30.companion.SmokeInstrumentation
```

Для виртуального геймпада приложен `tests/uinput-gamepad.c`. Используйте его только на отдельном отладочном x86_64-эмуляторе с root-доступом и `/dev/uinput`: соберите `gcc -static`, скопируйте бинарник в `/data/local/tmp`, запустите через `adb shell`. Он создаёт виртуальный Linux-геймпад; записывая в `/data/local/tmp/m30-command` строку `тип код значение`, можно подавать реальные события подсистемы ввода. Например, `1 304 1` нажимает BTN_A, `1 304 0` отпускает, `3 16 -1` задаёт HAT_X влево, `3 17 -1` — HAT_Y вверх. Команда `-1 0 0` удаляет виртуальное устройство и завершает помощник. Эти проверки не проверяют Bluetooth-радиоканал и конкретную прошивку M30.

## Проверка на настоящем M30

1. Повторно подключите сопряжённый M30 одним нажатием START.
2. Проверьте все шесть лицевых кнопок, L/R, START/SELECT и диагонали; при необходимости назначьте их.
3. Удерживайте две кнопки одновременно, отпустите одну: вторая должна остаться подсвеченной.
4. Нажмите HOME/перейдите в другое приложение и вернитесь: залипших нажатий быть не должно.
5. Выключите контроллер во время удержания: приложение должно показать ожидание и убрать подсветку.
6. Переключите крестовину SELECT + ↑ / ← / → (5 секунд) и проверьте кнопки/оси заново.
7. Смените режим только после выключения контроллера, обновите профиль в приложении и проверьте назначения. Если требуется, удалите старую пару в настройках Bluetooth и создайте заново.
8. Отправьте JSON-отчёт через «Поделиться» для диагностики отличающейся прошивки.

Физического M30 в среде разработки нет: реальные Bluetooth-соединение, батарея и раскладки конкретной прошивки здесь не проверяются.
