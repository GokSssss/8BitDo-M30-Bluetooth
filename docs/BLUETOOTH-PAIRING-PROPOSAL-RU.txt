Поиск и сопряжение M30 из приложения — обсуждение, 28.10.2026

В 1.34 механизм Bluetooth-подключения не менялся: владелец задал вопрос на подумать.
Можно сделать собственный экран «Найти M30»: однократный ограниченный поиск,
список кандидатов, выбор и запуск createBond, результат через BOND_STATE_CHANGED.
Системное подтверждение принадлежит Android, скрывать/обходить его не обещать.
Сопряжение не равняется активному HID-подключению и появлению InputDevice.
Для некоторых прошивок TV после pairing может понадобиться системное меню
«Пульты и аксессуары»; не использовать скрытые API для гарантии подключения.

Фильтр кандидатов:
- При явном имени 8BitDo M30 — основная группа.
- Имя и BluetoothClass/UUID дают признаки, не доказательство модели; VID/PID
  InputDevice обычно доступны уже после подключения, не как готовый фильтр поиска.
- Обобщённые имена в режимах совместимости (например Pro Controller) могут
  совпадать с другими устройствами. Показывать отдельно как вероятные,
  не объявлять все 8BitDo или все геймпады M30 и не скрывать нужный режим без объяснения.
- Одинаковые M30 различать по идентификатору найденного устройства, не по имени.

Два пути:
1) Собственный discovery-экран BluetoothAdapter. Нужны BLUETOOTH_SCAN/CONNECT
   с runtime-разрешениями Android 12+, а на старых Android соответствующие
   legacy/location разрешения. Проверить требования Location Services по версии.
   Поиск останавливать при выборе/закрытии/таймауте, не держать фоновый опрос.
2) CompanionDeviceManager 26+: позволяет фильтр по имени/UUID и системный список
   кандидатов без ACCESS_FINE_LOCATION; но показывает системное согласие и
   не создаёт само соединение. Наличие companion_device_setup проверять на TV.

План отдельного будущего изменения: подтвердить реальные Bluetooth-имена M30
в используемых режимах и поведение pairing/HID на данном TV; затем реализовать
фильтр с состояниями «поиск / найден / сопряжение / подключение / готово / ошибка»
и явным системным запасным вариантом. Не требовать новое скан-разрешение ради
показа уже подключённого InputDevice в текущей версии.
